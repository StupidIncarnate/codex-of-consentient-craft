# Gateway trial plan

Plan only — no code written for this doc. Ten trial units, each 1-3 caller files plus their tests
and proxies, switched from an adapter import to a gateway import. Picked to cover the edge cases the
`node-fs.md` inventory and the design doc name, at the least churn per unit. `git status` at plan
time showed no uncommitted changes under any of these files (the only dirty/untracked paths are
`packages/bin/src/testing/index.ts`, `packages/bin/src/claude/**`, `packages/shared/statics.ts`,
`packages/shared/transformers.ts`, and the shared `gateway-locations` / `node-builtin` / transformer
folders — none of which this plan touches).

## Units 1-3: the three confirmed data-loss bugs

All three share one shape: a bare `catch {}` (or `.catch(() => null)`) around a read-plus-`JSON.parse`
turns "the file is corrupt or unreadable" into "the file is absent," and the caller then writes a
fresh file over the user's real settings. The fix in every case is `readJsonFileIfExists` from
`@dungeonmaster/node/fs/promises`: it still answers `null` on ENOENT (a fresh install stays fresh),
but EACCES and invalid JSON reject instead of collapsing to the same `null` — so the existing
`catch` has to come OUT, and the rejection has to reach the caller (thrown, or turned into an
explicit failed `InstallResult` — a decision for whoever builds the unit, not settled here).

## Coverage checklist against the assignment

- **Three data-loss bugs:** units 1-3, each with a corrupt-file test proving the write is skipped and the error surfaces.
- **One caller per gateway package:** node/fs read (5, 9's sibling reads, and 1-4 throughout), node/fs/promises write (1, 3, 4), node/child_process via bin/git (6), browser localStorage (7), npm wrapper — glob (5, 10) and testing-library render (8).
- **A pure pass-through that disappears:** unit 5's `fsReadFileAdapter` half.
- **A test file consuming an npm pass-through in a contract:** unit 9.
- **Spread across packages:** mcp (1, 3, 9, 10), hooks (2), config (4), tooling (5), siegelense (6), web (7, 8) — six packages.
- **Uncommitted-work check:** none of the ten units' files appear in the `git status` output quoted at the top.

## What each unit measures about lint, per the brief

Every unit that has a broker/responder/state file import `@dungeonmaster/node`, `@dungeonmaster/npm`
or `@dungeonmaster/bin` directly (units 1-7, 9-10) is expected to trip whichever import-boundary rule
currently restricts that folder to `adapters/`, `contracts/`, `statics/`, `errors/`, `guards/`,
`transformers/` and our own workspace packages — because none of today's rules know the gateway
packages are not "another outside package" in the old sense. That trip IS the measurement: each
report should name the exact rule and message (`enforce-import-dependencies` or whichever fires),
not route around it with a disable comment, per the brief's rule 2. Unit 8 is the one exception,
since a test file's import rules are already looser and testing-library is already reachable from
`widgets/` test files today.
