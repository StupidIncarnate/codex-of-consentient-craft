This path is the "has-start: no" terminal — per the walk guide's FORCING section,
`collectSubagentChainsTransformer` never builds a SUBAGENT_CHAIN at all from a transcript with no Task
tool-use line, so the whole walk collapses to "row is in_progress, clock is threaded, but no chain
element — and therefore no subagent-chain-duration element — ever appears." Every stress point below
targets that absence: does it stay a clean absence under pressure, or does something leak, crash, or
briefly render wrong.

Vectors skipped as not reachable/applicable to this narrow terminal: double-submit (nothing is
"submitted" on this path — an in_progress row auto-expands with no click), perf (a "renders nothing"
terminal has no volume axis to stress — one row or a hundred rows of the same shape prove the same
thing), replay (no request whose effect "lands" here — this is a pure read/render path).

## Stress points

1. [FAMILY: re-entry] Rapid open/close toggle. Collapse the execution row (click execution-row-header)
   then immediately re-expand it, several cycles in quick succession, while the row stays in_progress
   and its transcript carries no Task tool-use entry (has-start:no seeding). Wrong: a stray
   subagent-chain-duration element appears transiently mid-toggle, or a toggle throws a client
   exception, or the row freezes mid-transition. Surface: ui-state (dom query for
   `[data-testid="subagent-chain-duration"]` after every toggle) + console (no uncaught errors).

2. [FAMILY: re-entry] Navigate-away-and-back. `goto` a different route (e.g. the guild's quest list)
   then `goto` back to the same quest URL, remounting ExecutionPanelWidget fresh, same has-start:no
   work item still in_progress. Wrong: a previous mount's dangling subscription (the panel's shared
   60s clock binding) or leftover DOM leaks into the remount — either a duration element appears that
   shouldn't, or remount throws because a stale interval/ref from the first mount wasn't torn down.
   Surface: ui-state (dom query post-remount) + console.

3. [staleness] Live file removal under an open page. With the panel already open and rendered (no
   chain, no duration, has-start:no), delete the sub-agent tail file on disk
   (`<home>/.claude/projects/<encoded guildPath>/<sessionId>/subagents/agent-<agentId>.jsonl`) out
   from under the still-open page — no reload — then force a re-broadcast with a no-op status PATCH
   (the same two-step trick FORCING's notification-arrives uses). Wrong: instead of staying at the
   same clean no-duration render, the client or server throws trying to re-read a file that vanished.
   Surface: network (watch the quest-fetch/PATCH response for a 500) + console + ui-state.

4. [hostile-input] Path-traversal agentId. Seed the work item's `agentId` as a path-traversal-shaped
   string (e.g. `../../../etc/passwd`) instead of a normal id, so the server resolves
   `subagents/agent-<agentId>.jsonl` against a hostile suffix. Wrong: the server 500s, or worse,
   actually reads/serves content from outside the session's subagents directory. Correct is the same
   clean no-duration terminal (nothing real resolves). Surface: network (response status/body) +
   ui-state (still no duration element, no chain).

5. [configuration] Malformed tail-file line. The sub-agent tail file for `agentId` exists (satisfying
   has-start:no via absence of any Task line) but has one malformed line — invalid JSON mixed among
   otherwise-valid non-Task lines. Wrong: instead of "no Task tool-use found, render nothing" holding
   (still no-duration, still clean), a JSON.parse on the bad line throws and takes down the WHOLE
   execution panel render, not just this row. Surface: ui-state (execution-panel-widget itself intact)
   + console (no uncaught exception).

6. [boundary] Absent subagents directory, not absent Task line. The work item's sessionId is stamped
   and status in_progress + startedAt is set (satisfies now-threaded), but the entire `subagents/`
   directory is never created (as opposed to has-start:no's own seeding, which creates the directory
   and a tail file with no Task line). Wrong: the directory-not-found case is handled differently from
   the file-exists-but-no-Task-line case — e.g. an ENOENT thrown instead of the same clean no-duration
   terminal. Surface: ui-state + console + network.
