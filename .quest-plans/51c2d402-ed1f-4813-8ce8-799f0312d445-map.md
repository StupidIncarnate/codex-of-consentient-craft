## Facts read off the implementation (step 3)

- `SubagentChainWidget` (`packages/web/src/widgets/subagent-chain/subagent-chain-widget.tsx:177-185`)
  renders `data-testid="subagent-chain-duration"` only when `durationLabel !== null`.
- `subagentElapsedInputTransformer` returns `null` when `taskToolUse === null`; otherwise it builds
  `{startedAt, endedAt?, reportedDurationMs?, clockReading?}`.
- `subagentDurationLabelTransformer` returns `null` when there is no end point at all —
  no `reportedDurationMs`, no `endedAt`, no `clockReading`. That is the session view's normal case.
- `now` is passed to `SubagentChainWidget` from ONE place only: `ExecutionPanelWidget` →
  `ExecutionRowLayerWidget` → `ChatEntryListWidget`. `ChatPanelWidget` (the session-view chat panel)
  passes none. So a session transcript's unfinished chain has no `clockReading` and shows nothing.
- `collectSubagentChainsTransformer:152` sets `taskToolUse: entry` UNCONDITIONALLY, and
  `chatEntryContract`'s `timestamp` is required and non-nullable on every variant
  (`packages/shared/src/contracts/chat-entry/chat-entry-contract.ts:39,52,65,80,92,105,122,133`).
  **No real transcript can produce a chain whose Task tool-use timestamp is missing.** See
  `branch:session-no-start` below.
- `durationMs 270000` → `4m` (floor, never `4m30s`, never `5m`) — pinned by
  `subagent-chain-widget.test.tsx:1683`.
