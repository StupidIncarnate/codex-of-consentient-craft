# Flowrider map — flow `send-message-with-images`

Operation item 339d7ed2-43c1-4023-8af8-a0511cb25caf · 58 units · 5 walk paths.

## Surfaces (pasted verbatim from get-qa-checklist)

- api-call → the real HTTP exchange — the method and URL sent, and the real status code and response body read back
- file-exists → the real filesystem — the path on disk, and the actual contents of the file
- custom → a BEHAVIOURAL INVARIANT, not an I/O channel — drive the real path that should produce it, inspect the actual result or state it left behind, and reason about whether the invariant held. NEVER reduce it to "a request fired". A content search or static assertion is the correct check ONLY when the observable itself names one (for example "no file still references X"), and then the real output of that search IS the measured value — run it with discover({ grep, strict: true }), since a bare shell grep/rg/find is blocked outright in this repo
- ui-state → the rendered DOM in a real, attached, VISIBLE browser tab
- log-output → the real log stream or log file the running process writes
- process-state → the real OS process — that it is running or absent, its argv, or its exit code
- TERMINAL SURFACE → the end state itself — the values the flow says this terminal has, AND its side-effect surface: no orphaned row, no half-written file, the transaction rolled back, the message not silently consumed, no stuck spinner. A clean-looking error that corrupted state is still a defect
- BRANCH SURFACE → the state after this branch was actually taken — the bad value submitted, the rejection triggered, the empty state hit, the limit exhausted. A branch reached by assumption rather than by forcing it has not been measured

## Facts the whole map rests on

| Thing | Value |
|---|---|
| chat route | `POST /api/quests/:questId/chat` → `QuestChatResponder` |
| follow-up route | `POST /api/quests/:questId/followup` → `QuestFollowupResponder` |
| create route | `POST /api/guilds/:guildId/quests` → `QuestNewResponder` |
| images dir | `<DUNGEONMASTER_HOME>/guilds/<guildId>/quests/<questFolder>/images` |
| file name | `<crypto.randomUUID()>.<mediaType.split('/')[1]>` — `image/png` → `.png`, `image/jpeg` → `.jpeg` |
| rewrite | `pastedImageTokenSubstituteTransformer` — `(?<!!)\[Pasted Image (\d+)\]` → `![Pasted Image N](<abs path>)`, mapped by ORDINAL |
| trailer | `` `${prompt}\n\n<!-- dungeonmaster:images -->\nRead every image referenced above before answering.` `` — appended once, only when `!\[Pasted Image (\d+)\]\(([^)]+)\)` matches |
| argv | `['-p', <prompt>, '--output-format', 'stream-json', '--verbose', '--model', <model>, '--chrome', …]` |
| argv read-back | `claudeMockHarness({ guildPath }).readInvocations()` → `[{ resumeSessionId, prompt }]` from `<DM_HOME>/claude-queue/__by_cwd__/<enc>/invocations.jsonl` |
| 6-image reject | chat/follow-up answer **400** `{"error":"Array must contain at most 5 element(s)"}` |
| follow-up status reject | **400** `{"error":"Quest must be blocked, complete or merged for follow-up"}`, checked BEFORE any write |
| 500 body | `{ error: <thrown error's own message> }` — never a fixed sentence |
| toasts | `mantineNotificationsShowAdapter` → Mantine `<Notifications />` mounted in `AppRootWidget` |

**Spec corrections already written into the quest** (so the checklist and these briefs agree):
`check-server-error-text-in-toast` now names 400 + "Quest must be blocked, complete or merged for follow-up";
`check-write-failure-toast-text` now names "the exact error sentence that response body carried";
`check-create-post-carries-images` now names `/api/guilds/:guildId/quests`.

**Measured defect to confirm in GROUP 6:** `QuestNewResponder` parses `images` through `questNewBodyContract` and then drops it
(`packages/server/src/responders/quest/new/quest-new-responder.ts:54` destructures `{ message, questType }` only; the file never imports
`pastedImagePersistBroker`). So a create-surface send posts its images, gets 200, and the agent is handed bare `[Pasted Image N]`
placeholders. `check-new-quest-first-message` is expected to come back NOT PROVED.
