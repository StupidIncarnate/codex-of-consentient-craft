## Shape of the change

The rewrite runs in the user-line parse step (`parseUserStreamEntryTransformer`), per contract
`#image-serve-endpoint` and design decision `#images-served-by-path-not-by-quest`. That transformer
cannot reach a broker, so the server base URL is THREADED DOWN from the three brokers that build a
chat-line processor:

    questGetServerConfigBroker().baseUrl        (broker layer — reads port env → .dungeonmaster.json → 3737)
      → chatLineProcessTransformer({ serverBaseUrl })
        → streamJsonToChatEntryTransformer({ parsed, serverBaseUrl })
          → parseUserStreamEntryTransformer({ parsed, lineUuid, timestamp, serverBaseUrl })
            → imagePathToUrlTransformer({ content, serverBaseUrl })

`/api/images` lands in `pastedImageStatics` (shared) rather than in the orchestrator, because the
server's own route (`apiRoutesStatics`, the contract's `source`) has to read the same value and the
server's cell has NOT committed yet — so this side adds the shared key and reads it; it does NOT
touch `apiRoutesStatics`.
