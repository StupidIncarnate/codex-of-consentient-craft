# web — send-message-with-images

Operation e203cbe2-c047-42c2-87cb-2973e93660c5 · package web · flow send-message-with-images

Already on the branch (paste-image-into-composer cell): contenteditable ChatInputWidget, composer
serialize/parse transformers, ComposerAttachment contract, draft-images brokers, chat-composer
statics, ImageOverlayWidget. Missing: the send itself carries nothing — `handleSend` clears the
composer BEFORE the server answers, `images` is dropped at `quest-chat-content-layer-widget`'s
`handleSend`, and no broker POSTs an images key.

Transport decision: `msw/node` (2.12) does NOT intercept XMLHttpRequest — grep of
`node_modules/msw/lib/node` finds no `XMLHttpRequest`; only browser/native/iife carry it. So the new
XHR adapter gets a REAL proxy (registerSpyOn on `globalThis.XMLHttpRequest`) and the three send
broker proxies move off `StartEndpointMock` onto it. Their semantic method names are preserved, so
`use-quest-chat-binding.proxy.ts` and `quest-chat-content-layer-widget.proxy.ts` need no change.

The send signature every layer threads:

```ts
onSendMessage: (params: {
  message: UserInput;
  images?: readonly PastedImageUpload[];
  onProgress?: UploadProgressHandler;
}) => Promise<void>;   // resolves = accepted, rejects with the server's own error text
```

    objects and arrays.
  - No beforeEach/afterEach, no conditionals in test bodies, fresh proxy per test.
