## What the implementation actually does

Read at `execution-row-layer-widget.tsx`, `use-elapsed-tick-binding.ts`,
`duration-display-transformer.ts`, `elapsed-parts-transformer.ts`,
`elapsed-display-config-statics.ts`.

The row renders a figure exactly when `startedAt && elapsedEndPoint`, where
`elapsedEndPoint = completedAt ?? (isRunning ? now : undefined)` and `isRunning` is
`status === 'in_progress'`. `now` is one shared value from `useElapsedTickBinding({ enabled:
hasRunningWorkItem })`, held once by the panel at `execution-panel-widget.tsx:212`, refreshed every
`elapsedDisplayConfigStatics.refresh.tickMs` (60000).

`elapsedPartsTransformer` floors the millisecond gap to whole seconds and clamps a negative gap to
zero. `durationDisplayTransformer` reads both thresholds from statics and prints `<1m` under 60
seconds, `${totalMinutes}m` under an hour, `${hours}h` on a whole hour, `${hours}h${minutes}m`
otherwise.

## The blocker every brief has to carry

`questHarness.writeQuestFile` CANNOT seed `startedAt`. Its `workItems` parameter type has no such
field, and its write-mapping builds each item from an explicit key whitelist with no spread, so an
extra property is dropped in silence. `buildQuestJson` is the same. Nothing under
`packages/web/test/` contains the string `startedAt`.

So every browser walk here needs a new harness of my own that patches `startedAt` onto an
already-seeded quest file and re-announces it. Group 0 builds it. Nothing else can start first.

SERIALISATION — why every remaining group holds ONE file

  Each spec's RED FIRST step edits shared source, and every browser walk renders that same source.
  Two agents running at once means one agent's deliberate break turns the other's run red for a
  reason that has nothing to do with its own assertions, and the second agent reads that as a
  product defect. Giving them different files to break does not help: the absent walk, the tick
  walk and the finished walk all render rows that call elapsedPartsTransformer and mount
  useElapsedTickBinding, so a break anywhere in that chain reaches all of them. So the groups below
  go out ONE AT A TIME, each waiting for the previous to return.

  Order is chosen to learn the risky thing first: the tick walk goes before the rest, because it is
  the only file needing page.clock.install (faked timers, not just a faked Date), and if the panel
  will not run under faked timers every later estimate changes.
