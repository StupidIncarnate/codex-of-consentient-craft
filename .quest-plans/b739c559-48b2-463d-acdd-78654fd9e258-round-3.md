## TOOLING-ERROR

The guide's SEEDING section did not flag that the `operations[]` status enum is `pending | in_progress | complete` only — it does NOT accept `queued`, even though `workItems[].status` does. Seeding 3 "queued" rows for the later tick-count test with `operations[].status: "queued"` failed the WHOLE quest.json's zod parse (`Invalid enum value... received 'queued'`), producing a blank panel with the error surfaced only in `api-server.log` / the `ws` capture's `quest-load-failed` frame — exactly the blank-panel trap CONTROLS/TRAPS describes for a bad ISO timestamp, but for a different field. Fixed by seeding those operations at `"pending"` instead. Flagging so this guide gains the same "operations status enum excludes queued" note the next path walk needs.
