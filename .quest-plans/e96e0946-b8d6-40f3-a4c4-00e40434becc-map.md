### `packages/web/test/harnesses/subagent-duration/subagent-duration.harness.ts`   new

Seeds a main-session JSONL carrying a Task tool_use at a CHOSEN timestamp, its completion
tool_result, and optionally a `<task-notification>` at a chosen timestamp with or without a
`<duration_ms>` tag; plus the sub-agent's own JSONL file. Mirror
`session.harness.ts`'s `createBackgroundAgentSession` (lines 703-792) — it already builds exactly
this shape, with `<duration_ms>9033</duration_ms>` hardcoded inside `<usage>`. The harness this
group writes makes the timestamps and that tag CALLER-CHOSEN, which is the whole reason a new file
is needed.

Methods:
- `seedChain({sessionId, agentId, taskToolUseId, taskDescription, taskToolUseAt, notification?: {at, durationMs?}})`
- `appendNotification({sessionId, agentId, taskToolUseId, at, durationMs?})` — for GROUP 3
- `seedNestedChain({...})` — for spec 4; may instead reuse `sessions.createNestedSubagentSessionFiles`
  if that already takes caller timestamps

Omitting `durationMs` must omit the whole `<duration_ms>` tag, not emit an empty one — that is the
`duration-ms-no` branch, and an empty tag would reach the web as a parse failure rather than as an
absent field.

## TRAPS

- A chain renders in an execution row only when the work item carries `sessionId` and NO `agentId`.
  With an `agentId` the replay reads ONLY `<sessionId>/subagents/agent-<agentId>.jsonl`, so the
  parent session's Task tool-use line is never read and no chain is ever built. The replay case in
  `nested-subagent-rendering.e2e.ts` is the shape that works.
- An `in_progress` row auto-expands and renders its entries. A `pending` row renders its body as
  `null`, so every text assertion on it fails for a reason that has nothing to do with duration. A
  `complete` or `failed` row must be expanded by CLICKING it.
- `page.clock.install({time})`, never `setFixedTime` alone. Only a full install lets
  `fastForward` fire the panel's `setInterval` callback.
- `elapsed.installIntervalCounter()` runs BEFORE `page.goto`, or it counts nothing.
- Each spec needs its OWN `GUILD_PATH` under `/tmp/` — `/tmp/dm-e2e-subagent-duration-<concern>`.
  Two specs sharing one path collide when ward runs them in parallel.
- A `.e2e.ts` may declare NO function. `forbid-non-exported-functions` rejects a helper declared in
  a spec and the pre-edit hook refuses the write outright, so anything computed goes in the harness.
- `.not.toBeVisible()` is a Playwright matcher and IS allowed in a `.e2e.ts`. The `.not.*` ban
  covers Jest matchers only.
- Never edit `packages/web/playwright.config.ts`, and never edit a harness another flow owns
  (`elapsed-duration.harness.ts` is READ-ONLY for this pass — call it, do not change it).
- Never `git -C <path> …`, and never chain git with `&&` or pipe it into `head`/`tail`/`wc`. Both
  forms are refused outright and report as a permission wall that is not one.
