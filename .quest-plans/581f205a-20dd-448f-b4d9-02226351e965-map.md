# web · paste-image-into-composer

Operation item 581f205a-20dd-448f-b4d9-02226351e965.

## Shape

CHAT_INPUT becomes a `contenteditable` div. Its content model is `ComposerSegment[]`, DERIVED from the
DOM on every change (never the other way round), so native typing / Enter / IME / Playwright `.fill()`
keep working untouched. Only three gestures are intercepted:

| gesture | intercepted | why |
|---|---|---|
| paste of a text item | yes — `preventDefault` + insert at range | makes the four `#check-text-paste-*` provable in jsdom |
| paste of an image item | yes — `preventDefault` + validate/downscale/insert `<img>` | the feature |
| `beforeinput` `deleteContentBackward`/`deleteContentForward` with a COLLAPSED range whose adjacent node is a thumbnail | yes | one keystroke removes the whole `<img>` in every browser |
| `beforeinput` `insertText` while the composer HOLDS AT LEAST ONE THUMBNAIL | yes | the caret rules around an atomic `<img>` differ per browser, and this is the condition every typing observable describes |
| everything else — typing into a composer with no thumbnail, Enter, select-all-replace, non-collapsed delete, IME composition | NO | Playwright `.fill()` does select-all + `execCommand('delete')` + insertText; intercepting a non-collapsed delete breaks all 18 e2e call sites |

The thumbnail-present condition on the `insertText` intercept is chosen, not incidental. Every existing
e2e fills a composer holding no image, so all 18 call sites stay on the fully native path. Measured in
this repo's jsdom 26.1.0: `Range.insertNode` at a text offset splits `abcd` into `ab | IMG | cd`, and
`setStartAfter(img)` leaves a collapsed caret the next insert lands after.

Ladder arithmetic stays in a PURE transformer, canvas + IndexedDB stay behind adapters. jsdom has no
canvas, no `indexedDB`, no `createImageBitmap`, and `img.naturalWidth` is always 0.

## FOUND READING THE DIFF — one missing line, two defects

The composer has NO `onInput` handler, and `handleContentChanged` runs only from the paste, delete
and intercepted-insertText paths. Typing plain text into a composer holding no thumbnail therefore
reaches it never. Two consequences, both regressions against the `<textarea>` this replaced, whose
`onChange` fired on every keystroke:

1. A typed message is never written to localStorage. Type, close the tab, and the draft is gone.
2. `isEmpty` is never recomputed, so the placeholder stays painted over the text as it is typed.

The test file already shows the symptom without naming it: the serialises-identically test at :866
had to fire an empty-text PASTE to re-trigger a save, because typing would not.

Fix: add `onInput` on the contenteditable, calling `handleContentChanged`. That path must NOT rewrite
IndexedDB on every keystroke — compare the serialised attachmentId list against the last saved one
and skip the image write when it is unchanged. Five images at the byte ceiling is ~25 MB rewritten
per character otherwise.

## TRAPS

  Never `git -C <path> …` and never chain or pipe a git call — both come back refused. Call git bare.
  `--only lint,unit`, never `lint,test` — `test` expands to e2e and would spin the whole Playwright stack.
  The delete intercept fires ONLY on a collapsed range. Playwright `.fill()` does select-all + delete;
  intercepting that breaks all 18 e2e call sites that fill CHAT_INPUT.
  React must never own the contenteditable's children — render the div with NO children and mutate the DOM
  through the adapters, or every paste resets the caret.
  Statics, not literals: every threshold comes from `pastedImageStatics` in @dungeonmaster/shared/statics.
  `exactOptionalPropertyTypes` is on — omit an optional property, never pass `undefined`.
  `noUncheckedIndexedAccess` is on — array index reads are possibly-undefined.
  Tests may not import types from contracts; use `ReturnType<typeof Stub>`.
  No `beforeEach`/`afterEach`, no conditionals in tests, no `toEqual`/`toMatchObject`/`toContain`/`toHaveLength`.
  jsdom has no `indexedDB`, no canvas 2d context, no `createImageBitmap`, no `URL.createObjectURL`.
  Define the missing global in the adapter's PROXY (the `clipboard-write-adapter.proxy.ts` pattern), never in
  the adapter.
