## PASS 1 — enumerated stress points

The path under test is the SIMPLEST branch in the flow: the widget's own gate is
`startedAt && elapsedEndPoint` (execution-row-layer-widget.tsx). The happy-path "key omitted
entirely" case is already C+F confirmed (#check-no-elapsed-without-started-at). Vectors that need a
user action or a second caller (double-submit, replay, concurrency, configuration, staleness) do not
apply — this path is a pure render with no mutation and no config read before the gate. `perf` is not
reachable meaningfully off one row. What remains, and what FAMILY hostile-input calls for directly, is
hostile shapes of the SAME field that are not the plain "omitted key" the happy path already covers —
does the app degrade gracefully (no figure, this row only) or does a malformed value crash wider than
the row (whole quest.json parse, whole panel blank, unhandled exception, injection surfacing
somewhere)?

1. `startedAt: null` (explicit JSON null, not an omitted key). Way it goes wrong: the schema that
   parses a work item may accept only a valid datetime string or an omitted key (`.optional()`) but
   reject explicit `null` (which needs `.nullish()`), throwing on the WHOLE quest.json parse — so a
   single row with an explicit null blanks every row on the panel, not just itself. Surface:
   contract/schema test for the work item parser; browser `execution-panel-widget` box reading
   (present:false for the WHOLE panel, not just the row) plus `api-server.log`'s zod error.

2. `startedAt: ""` (empty string). Way it goes wrong: same class of question as (1) but for a value
   that IS a string yet fails datetime-format — confirm it's rejected the same way as null rather than
   slipping past a looser "is it a string" check and rendering garbage. Surface: same schema/contract
   layer; browser box reading on `execution-row-duration` for any rendered text at all.

3. `startedAt: "not-a-real-date"` (garbage non-ISO string). Way it goes wrong: confirms the
   datetime-FORMAT check itself (not just string-vs-non-string) is what's enforced, and that the
   failure mode is consistent across every "wrong shape of string," not special-cased for empty-string
   alone. Surface: schema/contract test; browser panel-blank / console error.

4. `startedAt` as a raw JSON number (epoch ms, e.g. `1767225600000`) instead of a string. Way it goes
   wrong: JS truthiness treats any nonzero number as "present" — if a looser type slipped past
   validation into the widget, the row could render a nonsensical duration (NaN, or an enormous
   figure) instead of either the documented "no figure" state or a clean rejection. This is a
   type-confusion gap distinct from the malformed-string cases above. Surface: schema/contract layer
   (does it reject non-string types at all); browser box reading on `execution-row-duration` for
   garbage text if it slips through.

5. `startedAt` as an oversized string (~100,000 characters). Way it goes wrong: a well-formed
   rejection path (like case 3) might still hang or behave differently on an extreme payload size than
   on a short garbage string — regex-based datetime validation can pathologically backtrack on crafted
   long input. Confirm the rejection is the same clean rejection, not a hang or a different uncaught
   exception. Surface: schema/contract-level test with the oversized string.

6. `startedAt` containing an injection-style value (e.g. `"<script>alert(1)</script>"`) or embedded
   control characters. Way it goes wrong: two distinct surfaces — (a) is it caught by the same
   datetime-format rejection as any other garbage string (expected), or (b) if any code path ever
   echoes the invalid raw value back (an error message rendered to the DOM, a log line
   double-interpreted), does the payload surface unescaped. Surface: schema/contract test for
   rejection; `console`/`dom` siege reading for any unescaped artifact if driven.
