## Stress points

1. [hostile-input] durationMs negative (`-5000`). Seed the notification's `duration_ms` as a negative
   number. Wrong: `subagent-chain-duration` renders a negative band (e.g. "-1m"), `NaN`, or throws,
   instead of flooring at the same `<1m` a tiny positive value gets.

2. [hostile-input] durationMs zero (`0`). Wrong: renders blank/NaN, or gets treated as falsy and
   conflated with "no duration reported" (dropping to the timestamp-gap or no-duration branch)
   instead of `<1m`.

3. [hostile-input] durationMs a non-integer float (`4380000.7`). Wrong: the fractional part leaks into
   the rendered band (something other than the clean `1h13m` a whole-number equivalent renders), or
   the figure reads `NaN`.

4. [hostile-input] durationMs holding non-numeric garbage text (`"not-a-number"`) rather than a
   number — reachable because `subagentDurationHarness`'s own notification builder stringifies
   whatever it is handed straight into the `<duration_ms>` XML tag with no numeric validation
   (`buildNotificationContent`'s `String(durationMs)`), so a hostile CALLER (or a buggy upstream CLI)
   can put ANY text there, not just digits. Wrong: `NaN` or a garbled label renders, or the parse
   throws and takes down more than the one chain (the whole panel render, not just this row).

5. [hostile-input] durationMs far past any sane range (`999999999999999999999`, past
   `Number.MAX_SAFE_INTEGER`). Wrong: renders `Infinity`, a garbled huge band, or `NaN`.

6. [hostile-input] durationMs explicit `null` with the key still present (distinct from the key being
   omitted, which is the documented has-duration-ms:"no" branch). Wrong: behaves unpredictably rather
   than falling cleanly to the same timestamp-gap path an omitted key takes — e.g. renders blank instead
   of computing the gap, or throws on a null arithmetic operation.

7. [hostile-input] Task description script-shaped text (`<script>alert(1)</script>` as the Task call's
   `description`), rendered in `SUBAGENT_CHAIN_HEADER` beside `subagent-chain-duration`. Wrong: the
   string renders as live markup (an actual `<script>` element or event-bearing attribute lands in the
   DOM) rather than literal escaped text, or its presence breaks/hides the adjacent duration figure.

8. [hostile-input] Task description very long (20,000 chars) AND carrying control characters/embedded
   newlines (`\x00`, `\x07`, `\n`, ` `) mixed in. Wrong: a render crash or console error, or the
   duration figure becomes unreadable/displaced because the hostile description broke the header's
   layout.

9. [hostile-input] Malformed, non-ISO Task tool-use timestamp (`"not-a-date"` as the Task tool-use
   entry's `timestamp`). Wrong: despite durationMs taking precedence for the figure itself
   (`dd-finished-figure`), the contract still requires a start (`startedAt` is required on
   `SubagentElapsedInput`) — a malformed value crashes the parse/render (500, or a client exception)
   instead of failing cleanly, or a `NaN`/garbled figure leaks through.

10. [hostile-input] Wildly future-dated Task tool-use timestamp (year 9999, e.g.
    `"9999-12-31T23:59:59.000Z"`). Wrong: even though durationMs should still win for the rendered
    figure, the far-future start corrupts entry ordering/sorting elsewhere in the transcript in a way
    that also corrupts or duplicates the rendered chain/duration, or throws on some date-arithmetic
    path that assumed a sane range.

11. [hostile-input] Path-traversal-shaped agentId (`../../../etc/passwd`-style) used to key/resolve the
    chain's own sub-agent transcript file. Wrong: the server 500s in a way that leaks a path/stack, or
    — worse — actually resolves and serves content from outside the session's own subagents directory,
    corrupting or leaking data into the chain that feeds the duration figure. Correct is a clean
    failure (no chain data resolves from the hostile suffix) with the rest of the page intact.
